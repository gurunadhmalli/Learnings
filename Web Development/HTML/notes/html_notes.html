HTML — Complete Notes

Learning + interview reference. Covers structure, elements, forms, semantics, accessibility, and common interview questions.

1. Introduction to HTML

HTML (HyperText Markup Language) is the standard markup language used to structure content on the web. It is not a programming language — it has no logic/conditionals — it describes the structure and meaning of content using elements (tags). Browsers parse HTML into the DOM (Document Object Model), which CSS styles and JavaScript manipulates.

  • Current version: HTML5 (living standard maintained by WHATWG, with W3C also publishing).
  • Markup language, not a scripting/programming language — no variables, loops, or conditions.
  • HTML + CSS + JavaScript = the three core front-end web technologies (structure, presentation, behavior).

Minimal Boilerplate

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Page Title</title>
</head>
<body>
    <h1>Hello World</h1>
</body>
</html>
Note: <!DOCTYPE html> is not an HTML tag — it's an instruction telling the browser to render the page in standards mode (HTML5) instead of "quirks mode" (legacy, inconsistent rendering).

3. Elements, Tags & Attributes

An element = opening tag + content + closing tag: <p>text</p>. A tag is just the markup itself (<p>). Attributes live inside the opening tag as name="value" pairs and provide extra info/behavior.

Void (self-closing) elements

These have no closing tag and no children: <br>, <hr>, <img>, <input>, <meta>, <link>, <source>, <col>, <area>, <wbr>, <track>, <embed>, <base>.

Global Attributes (usable on almost any element)

AttributeUse
idUnique identifier — one per page — used for anchors, CSS, JS getElementById.
classNon-unique grouping label — reusable across many elements — used for CSS/JS.
styleInline CSS (avoid for maintainability; fine for quick tests).
titleTooltip text shown on hover.
data-*Custom data attributes, e.g. data-user-id="42", read via JS element.dataset.userId.
hiddenBoolean — hides element (like display:none).
tabindexControls keyboard-tab focus order.
contenteditableMakes element editable by the user in the browser.
draggableEnables HTML5 drag-and-drop.
lang, dirLanguage and text direction (ltr/rtl).
id vs class: id must be unique per page and has higher CSS specificity; class can repeat and is meant for reusable styling/grouping.

6. Block vs Inline vs Inline-Block

TypeBehaviorExamples
BlockStarts on a new line, takes full available width by default, respects width/height/margin/padding on all sides.div, p, h1-h6, ul, ol, li, table, form, section, header, footer
InlineFlows within text, only takes as much width as content needs, ignores width/height and top/bottom margin.span, a, strong, em, img*, label, input*
Inline-blockFlows inline like text but respects width/height/margin/padding.Set via CSS display:inline-block (e.g. img, button default to this-ish behavior)

* img and input are technically "replaced inline elements" — inline by default but they do honor width/height because their content is external.

7. Lists

<!-- Unordered -->
<ul>
  <li>Tea</li>
  <li>Coffee</li>
</ul>

<!-- Ordered -->
<ol start="3" type="A">
  <li>Step one</li>
  <li>Step two</li>
</ol>

<!-- Description list -->
<dl>
  <dt>HTML</dt>
  <dd>Markup language for structuring web content</dd>
</dl>
  • <ul> = unordered (bullets), <ol> = ordered (numbers/letters), <dl> = description/definition list (dt = term, dd = description).
  • Lists can be nested by placing a full <ul>/<ol> inside an <li>.
  • ol attributes: start, reversed, type (1, A, a, I, i).

8. Links & Navigation

<a href="https://example.com" target="_blank" rel="noopener noreferrer">Visit</a>
<a href="mailto:someone@example.com">Email us</a>
<a href="tel:+911234567890">Call us</a>
<a href="#section2">Jump to Section 2</a>
<a href="file.pdf" download>Download PDF</a>
AttributePurpose
hrefDestination URL, anchor (#id), mailto:, tel:, or file path.
target="_blank"Opens link in a new tab.
rel="noopener noreferrer"Security best practice with target="_blank" — prevents the new page from accessing window.opener (tab-nabbing risk).
downloadForces browser to download instead of navigate.
Interview note: always pair target="_blank" with rel="noopener" to avoid a known security vulnerability (reverse tabnabbing).

9. Images & Media

<img src="photo.jpg" alt="Description of image" width="300" height="200" loading="lazy">

<figure>
  <img src="chart.png" alt="Sales chart">
  <figcaption>Fig 1. Quarterly sales</figcaption>
</figure>

<!-- Responsive images -->
<img src="small.jpg" srcset="small.jpg 480w, large.jpg 1024w"
     sizes="(max-width: 600px) 480px, 1024px" alt="Responsive">

<picture>
  <source srcset="img.webp" type="image/webp">
  <img src="img.jpg" alt="Fallback">
</picture>

<video controls width="400">
  <source src="movie.mp4" type="video/mp4">
  Your browser doesn't support video.
</video>

<audio controls>
  <source src="sound.mp3" type="audio/mpeg">
</audio>
  • alt is mandatory for accessibility — describes the image for screen readers and shows if the image fails to load. Use alt="" (empty) for purely decorative images.
  • loading="lazy" defers off-screen image loading — improves performance.
  • picture/source let you serve different formats/resolutions based on browser support or screen size.
  • video/audio: controls shows the native player UI; multiple <source> tags provide format fallbacks.

13. Iframes & Embeds

<iframe src="https://example.com" width="600" height="400"
        title="Embedded content" loading="lazy" sandbox></iframe>
  • <iframe> embeds another full HTML document inside the current page (e.g. YouTube embeds, maps).
  • <embed> / <object> embed external resources (PDFs, Flash-era plugins, SVG) — object supports fallback content, embed doesn't.
  • sandbox attribute restricts what the embedded page can do (scripts, forms, popups) — important for security when embedding untrusted content.
  • Always give an iframe a title for accessibility.

15. Accessibility (a11y)

  • Use semantic HTML first — a native <button> is keyboard-accessible and announced correctly by screen readers automatically; a <div onclick> is not, by default.
  • Every <img> needs meaningful alt text (or alt="" if purely decorative).
  • Every form input needs an associated <label>.
  • ARIA (Accessible Rich Internet Applications) attributes like role, aria-label, aria-hidden, aria-expanded fill gaps when semantic HTML alone isn't enough (e.g. custom widgets) — the golden rule: "No ARIA is better than bad ARIA" — prefer native elements first.
  • Ensure sufficient color contrast and that the page is fully operable via keyboard (tabindex, focus states).
  • lang attribute on <html> lets screen readers use correct pronunciation rules.

16. SEO Basics (HTML-level)

  • One clear, descriptive <title> and <meta name="description"> per page.
  • One <h1>, logical heading hierarchy (h2 nested under h1, etc.) — helps search engines understand content structure.
  • Descriptive alt text on images (also helps image search).
  • Semantic elements (article, nav, main) help crawlers understand page structure.
  • Meaningful, descriptive link text (avoid "click here").
  • <link rel="canonical"> to avoid duplicate-content penalties.

19. Interview Q&A

What is the difference between HTML and HTML5?

HTML5 introduced semantic elements (header, nav, article, etc.), native audio/video support, canvas for graphics, new form input types & validation attributes, offline/local storage APIs, and removed dependency on plugins like Flash. It's also more lenient/standardized in parsing across browsers.

What are semantic elements and why do they matter?

Elements whose tag name conveys meaning about their content (e.g. <nav>, <article>) rather than being purely presentational (<div>). They improve accessibility (screen readers understand structure), SEO (search engines parse content better), and code readability/maintainability.

Difference between <div> and <span>?

<div> is a block-level generic container (starts new line, full width); <span> is an inline generic container (flows within text). Both carry no semantic meaning on their own.

Difference between id and class?

id must be unique per page, used for a single specific element (anchors, JS hooks, higher CSS specificity). class can be reused across many elements for shared styling/behavior.

What's the difference between src and href?

src (source) embeds/replaces the element with the external resource — used on <img>, <script>, <iframe> — the page waits for/renders that resource inline. href (hypertext reference) links to a resource without embedding it — used on <a>, <link> — creates a relationship/navigation, doesn't block rendering.

What are void/self-closing elements? Name a few.

Elements that cannot have children/closing tags because they represent a single point of content: <img>, <br>, <hr>, <input>, <meta>, <link>, <source>, <area>.

GET vs POST in forms — when to use which?

GET: appends data to the URL as a query string; visible, bookmarkable, cacheable, size-limited (~2000 chars) — use for non-sensitive reads/searches. POST: sends data in the request body; not visible in URL, no practical size limit, not cached by default — use for sensitive data (passwords), file uploads, or data that changes server state.

disabled vs readonly on a form field?

Both prevent editing, but a disabled field is skipped entirely on submit (its value is not sent, and it's unfocusable/unstyleable as normal), while a readonly field's value is submitted and the field can still be focused/selected/copied.

Why does <label for="..."> matter?

It programmatically ties a label to its input by matching for to the input's id. This lets clicking the label focus/toggle the input and lets screen readers announce the label when the field receives focus — required for accessible, usable forms.

What is the DOM?

The Document Object Model — the browser's in-memory, tree-structured representation of the parsed HTML document. JavaScript reads/manipulates the DOM (not the raw HTML text) to change what's rendered.

What does <!DOCTYPE html> do?

It's a required declaration (not a tag) that tells the browser to render the page in HTML5 "standards mode" instead of the inconsistent legacy "quirks mode." It must be the very first line of the document.

Block vs inline elements — how do you tell which is which, and does it matter?

Block elements start on a new line and take full available width (div, p, h1-h6, ul); inline elements flow within the surrounding text and only take as much width as needed (span, a, strong). It matters for layout: block elements accept width/height/vertical margin, inline elements largely ignore them (this is also overridable via CSS display).

How do you make a responsive image?

Use srcset + sizes on <img> to let the browser choose the best resolution image for the viewport/pixel-density, or use <picture> with multiple <source> elements to serve different formats (e.g. WebP with a JPEG fallback) or art-directed crops per breakpoint.

What's the purpose of the viewport meta tag?

<meta name="viewport" content="width=device-width, initial-scale=1.0"> tells mobile browsers to use the actual device width as the layout viewport width and set zoom to 100% initially — without it, mobile browsers default to a desktop-width viewport (~980px) and shrink the whole page, breaking responsive CSS.

Difference between iframe and embed/object?

<iframe> embeds a full separate HTML document (its own browsing context) — e.g. a YouTube video or map. <embed>/<object> embed external non-HTML resources via a plugin/renderer (PDFs, SVGs); <object> additionally supports fallback content between its tags if the resource fails to load.

What are ARIA attributes and when should you use them?

Accessible Rich Internet Applications attributes (role, aria-label, aria-hidden, aria-expanded, etc.) add accessibility semantics that native HTML can't express — mainly needed for custom JS widgets (custom dropdowns, tabs, modals). Rule of thumb: prefer a native semantic element first; only add ARIA when no native element covers the behavior, since incorrect ARIA is worse than none.

How is HTML parsed — is it case sensitive, and is it forgiving of errors?

HTML tag/attribute names are case-insensitive (lowercase is convention/best practice), and browsers use a very forgiving/error-correcting parser (per the HTML5 parsing spec) — e.g. unclosed tags are often auto-closed based on well-defined recovery rules, unlike strict XML/XHTML which would simply fail.

Cookies vs localStorage vs sessionStorage?

Cookies (~4KB) are sent with every HTTP request to the server and can have an expiry date. localStorage (~5-10MB) persists indefinitely on the client only, never sent to the server automatically. sessionStorage behaves like localStorage but is cleared when the browser tab closes. Use cookies for data the server needs on every request (auth tokens, session IDs); use Web Storage for client-only state.

What's the difference between HTML and XHTML?

XHTML is HTML rewritten to follow strict XML syntax rules — every tag must be closed, attributes must be quoted, tags must be properly nested, and a single syntax error breaks the entire page. HTML5 is more forgiving and browser-parsed with defined error-recovery behavior, which is why HTML5 (not XHTML) became the dominant standard.
